# 確率的進化ゲーム

[日本語](../ja/evolution.md) · [中文](../zh-CN/evolution.md) · [English](../en/evolution.md)

## 授業での進め方

1. `/teacher` で **Stochastic Evolutionary Games** を選びます。ゲーム、実験名、利得表、教員パスワードを確認してルームを作成します。ゲーム・利得・ラウンドの設定は作成後に固定します。表示言語（日本語・中国語・英語）は教員・学生が各自のヘッダーで選び、各自のブラウザーに保存されます。
2. 学生にルームコードと入口 `/` を共有します。学生はニックネームと4桁の暗証番号で入室し、待機カードの「ルール」でこのルームのルールと利得を確認できます。
3. 実人数とグループ別予定人数を確認して入室を締め切ります。各グループに2人以上必要です。締切時に人数差が最小になるよう無作為に分け、所属を固定します。要求ゲームでは各グループ内で人数差が最小のA・B両側に割り当てます。奇数の場合、どちらを1人多くするかも抽選します。教員が配分を確認して開始します。
4. 各回で非公開の選択を1回確定します。再読み込み・再入室後も確定した回答を保持します。両者が回答すると、その組の選択・双方の利得と自分の累計を表示します。学生は自分の履歴を確認でき、教員は進行中・終了後にグループ別の推移を閲覧・ダウンロードできます。

受付中はグループ数を変更できます。手動で締め切るか、受付タイマー（5〜3600秒、初期値60秒）を開始します。一時停止・再開・リセットも可能です。期限時に各グループが2人以上なら自動で確定し、足りなければ受付を続けます。実験開始前に受付を再開でき、次の締切で名簿を再抽選します。

終了したラウンドは明るい緑で示します。現在のラウンドは二重丸で、デモでは金色、正式実験では紫です。開始前のラウンドは灰色の破線で示します。教員・学生は残り時間を分秒の時計とバーで確認できます。教員は回答・結果表示を一時停止・再開し、現在の段階を上限に残り時間を30秒短縮できます。回答を早く締め切ると結果表示へ（最終回は終了）、結果表示から次回へ進めます。実験の早期終了は確認後に実行します。清算済みの利得は保持し、未成立の組は `interrupted` とし提出済み回答を残して利得を欠測とします。研究JSONの `controls` は教員操作の時刻・回を記録します。個人記録は新しい順に表内でスクロールできます。

## 設定と利得

| 設定                 | 初期値 | 範囲    |
| -------------------- | ------ | ------- |
| 独立グループ数       | 1      | 1–32    |
| ラウンド数           | 10     | 1–100   |
| 回答時間             | 30秒   | 5–600秒 |
| ラウンド間の結果表示 | 8秒    | 3–120秒 |

- **協調ゲーム。** 戦略名2個と4マスの利得8個を変更できます。初期の行・列は鹿、兎で、行順に (4,4)、(0,3)、(3,0)、(2,2) です。行・列の位置は各回の抽選で決まり、自分の位置を画面で確認できます。非対称な表では位置によって利得が変わります。
- **ナッシュ要求ゲーム。** 両側は同じ総額と、0から総額までの相異なる2–12個の要求額を使います。初期値は総額1、要求額1/3・1/2・2/3です。合計が総額以下なら各自が要求額を得ます。超えると双方0です。整数、小数、正の分母をもつ分数を有理数で正確に計算し、総額0.3に対する0.1と0.2も成立します。

## 組合せ・時計・欠席

毎回、同じグループ内で組み直します。要求ゲームはAとBの間で組みます。連続して同じ相手と組むことがあります。奇数グループでは1人が休みます。対象者（要求ゲームでは人数の多い側）のうち過去の休みが最も少ない人から無作為に決めます。休みの回には回答も利得もありません。

全組が回答するかサーバーの期限が到来するとその回を終了します。結果表示時間が過ぎると、次の認証済みアクセスで次回を開始します。全員が画面を閉じた場合は再アクセス時に前回の期限を適用し、開始時刻から次回の回答時間を確保します。最終回は終了画面へ進みます。片方が未回答なら双方の当回利得を欠測とし、提出済みの選択を保持します。本人の時間切れと相手の未回答を区別し、確定利得がゼロのときは0を記録します。

画面を閉じても組合せに残ります。基礎版に永久退出・交代はありません。同じニックネームと暗証番号で再入室できます。締切後の新規入室はできません。サーバーとの接触が15秒を超えて途切れた区間を通信中断の可能性として記録します。タブのバックグラウンド化でも生じます。区間は最終接触の15秒後から再接触・出力時点・実験終了までで、回答の時間切れとは別に扱います。

## 集計と出力

教員はグループごとの各回を閲覧できます。選択割合の分母は提出された回答数で、相手が未回答の場合も含みます。要求ゲームはA・B別に計算します。組合せ頻度は行・列の順（要求ゲームではA・B）です。一致率は清算済みの組で両者が同じ戦略を選んだ割合で、利得表を変更した場合も定義は同じです。決裂率は要求額合計が総額を超えた組が清算済みの組に占める割合です。分母が0なら横線を表示します。

**研究データ JSON** は全設定、コード、匿名名簿、所属・側、通信中断区間、各グループの各回の集計、個人別の生データを含みます。**回答 CSV** は休みも含めて1人1回1行です。ルーム・グループ・回・匿名IDでJSONと照合できます。選択番号は設定順に0から始まります。時刻はUnixミリ秒、`seenAt` はその人の回答画面へのアクセスをサーバーが初めて観測した時刻、`submittedAt` は受信時刻です。割当・組合せ・アクセス・提出の人数を区別します。`pay` と `total` は正確な数値の文字列です。欠測はJSONのnull・CSVの空欄です。`bye`（休み）、`timeout`（本人時間切れ）、`unmatched`（相手が未回答）、`settled`（清算済み）を識別できます。ニックネーム、暗証番号、認証情報は出力しません。

## 研究上の解釈

[講義資料16–21頁](../../../material/Session3-2.pdf)はリスク支配とナッシュ交渉解を扱います。[KMR補足3–7、17–18頁](../../../material/Session3-2KMR補足.pdf)では平均利得、適応規則、まれな突然変異を扱い、要求ゲームの例は片側12人です。本実験では各回で1組だけを経験し、自分の組の結果を見て各自が自由に選びます。自動の最適反応や人工的な突然変異はありません。リスク支配均衡や対称な要求例での折半は検証対象であり、設定の変更で予測も変わりえます。データ収集前に、フィードバック、側の固定、人数、時間、未成立の組の扱い、収束の評価方法を担当教員と確認してください。
