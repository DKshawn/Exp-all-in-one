# 随机演化博弈

[日本語](../ja/evolution.md) · [中文](../zh-CN/evolution.md) · [English](../en/evolution.md)

## 课堂操作

1. 在 `/teacher` 选择 **確率的進化ゲーム**，切换日文、中文或英文，选择博弈模式，命名房间，预览收益并设置房间密码。博弈、收益和轮次设置在建房后锁定。
2. 分享房间代码和学生入口 `/`。学生以昵称和四位 PIN 入室，在等待页查看规则。
3. 教师检查实际入室人数和预计群体规模后截止入室。系统随机分成规模尽量相等且固定的独立群体，每群至少两人。需求博弈还会在各群内固定分配人数尽量相等的 A、B 侧。奇数群体随机决定哪一侧多一人。教师查看分配后确认开始。
4. 每轮私下选择并确认一次。刷新或重新登录会恢复已提交的选择。配对双方均提交后即可看到本轮双方的选择、收益及自己的累计收益。个人历史可回看。教师可在运行中或结束后查看各群过程并导出数据。

入室期间可调整独立群体数。教师可手动截止，或启动 5–3600 秒的入室截止计时器（默认 60 秒）。可暂停、继续或重置计时。到期时若每群至少两人则自动截止，否则继续接收学生。开始前可重新开放入室，再次截止时按新名单重新随机分组。

师生页面共用轮次条、分秒倒计时和进度条。教师可暂停和继续作答或反馈，或将当前阶段的剩余时间缩短 30 秒，最多推进至阶段边界。提前结束本轮会进入反馈（最后一轮直接结束），反馈中可直接进入下一轮；终止实验须确认。已结算收益保留，未完成配对标记为 `interrupted`，原选择保留，收益留空。研究 JSON 的 `controls` 记录教师操作、时间和轮次。学生的个人记录最新在上，仅在记录表内滚动。

## 参数与收益

| 参数         | 默认值 | 可设范围 |
| ------------ | ------ | -------- |
| 独立群体数   | 1      | 1–32     |
| 轮数         | 10     | 1–100    |
| 作答时间     | 30 秒  | 5–600 秒 |
| 轮间反馈时间 | 8 秒   | 3–120 秒 |

- **协调博弈。** 可修改两个策略名和四格中全部八个收益。行列默认均为鹿、兔，按行依次为 (4,4)、(0,3)、(3,0)、(2,2)。每轮重新抽取行方与列方，学生可见自己的位置，以便解释非对称矩阵。
- **Nash 需求博弈。** 两侧共用可分配总额和 2–12 个互异的需求选项，取值介于 0 与总额之间。默认总额 1，选项为 1/3、1/2、2/3。需求之和不超过总额时各得所求，超过时双方收益均为 0。整数、小数与正分母分数采用有理数精确计算，例如总额 0.3 可恰好满足 0.1 和 0.2。

## 配对、计时与缺席

各群独立重抽，需求博弈只跨 A/B 匹配，允许连续遇到同一人。奇数群每轮有一人轮空。在可轮空的人中（需求博弈为人数较多的一侧）优先选择历史轮空次数最少者，同次数随机抽取。轮空者无须作答，该轮收益留空。

全部配对提交或服务端截止时间到达时结束本轮。反馈期过后，由下一次已认证的房间请求开启下一轮。如果所有人关页，恢复访问时应用上一轮截止时间，到期后开启完整的新作答窗口。最后一轮直接进入结果页。一方缺答时双方当轮收益均留空，保留已提交一方的原选择，分别记录对方缺答和本人超时。实际收益为零时记录 0。

关页不会撤销席位，之后仍参与匹配。基础版没有永久退出或替补流程。使用原昵称和 PIN 可重入，截止后不能新增参与者。连续超过 15 秒没有服务端联系即记录疑似断线，也可能是标签页进入后台。记录区间从最后联系后 15 秒到下次联系、导出或实验结束；作答超时单独记录。

## 读取和导出数据

教师表格按群体逐轮展示。策略比例的分母为已提交选择数，含对方缺答时保留的选择，需求博弈 A/B 两侧分别计算。配对频数按行方、列方顺序（需求博弈为 A/B）。协调成功率定义为已结算配对中选择相同的比例，自定义矩阵也采用此口径。谈崩率为需求之和超过总额的配对占已结算配对的比例。分母为空时显示横线。

**研究数据 JSON** 包含完整配置、房间代码、匿名名单、固定群体及侧别、心跳缺失区间、每群每轮统计和逐人逐轮原始记录。**原始记录 CSV** 每名入组者每轮一行，含轮空记录，可用房间、群体、轮次和匿名 ID 与 JSON 联结。选择索引按配置顺序从 0 起。时间为 Unix 毫秒，`seenAt` 是服务器第一次观察到该参与者访问本轮作答窗口的时间，`submittedAt` 是收到提交的时间。人数分别统计已分组、已配对、已访问和已提交。`pay`、`total` 用字符串保存精确数值。缺失在 JSON 中为 null，在 CSV 中为空。状态含 `bye` 轮空、`timeout` 本人超时、`unmatched` 对方超时和 `settled` 已结算。导出不含昵称、PIN 或登录凭证。

## 研究解释

[主讲义第 16–21 页](../../../material/Session3-2.pdf)介绍风险占优与 Nash 讨价还价解。[KMR 补充材料第 3–7、17–18 页](../../../material/Session3-2KMR補足.pdf)使用平均收益、适应规则与罕见突变，需求博弈的示例每侧有 12 人。真人基础版每轮只观察一次私人配对，自主选择。程序不代为最佳反应，不引入人工突变。风险占优协调和对称需求例中的平分均为待检验预测，改变参数可能改变预测。正式采集前，应与教授确认反馈范围、固定侧别、人数、计时、未完成配对的处理和收敛判定方法。
