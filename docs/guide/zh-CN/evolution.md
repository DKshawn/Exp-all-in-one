# 随机演化博弈

通过页眉右上角的地球图标选择的语言，会在同一浏览器中沿用到其他实验。

[日本語](../ja/evolution.md) · [中文](../zh-CN/evolution.md) · [English](../en/evolution.md)

浏览器限制保存偏好时，仍可在当前页面切换语言。手机上也能直接编辑每格收益，长数值可在输入框内移动光标查看。

正式房间最多登记 5,000 人。「演示人数」可设为 2 至 5,000 人，包含自己操作的一个席位，默认 6 人。

## 课堂操作

1. 在 `/teacher` 选择 **Stochastic Evolutionary Games**，选择博弈模式，命名房间，设置收益和房间密码。博弈、收益和轮次设置在建房后锁定。教师和学生各自在页眉选择日文、中文或英文，语言只保存在自己的浏览器里。
2. 在参与者分组栏点击「复制入室链接」，将链接分享给学生。打开链接时房间代码已填好。学生以昵称和四位 PIN 入室。原版协调博弈和 Nash 需求博弈的学生可以在等待卡片中点「规则」查看本场规则和收益。
3. 教师检查实际入室人数和预计群体规模后截止入室。系统随机分成规模尽量相等且固定的独立群体，每群至少两人。需求博弈还会在各群内固定分配人数尽量相等的 A、B 侧。奇数群体随机决定哪一侧多一人。教师查看分配后确认开始。
4. 协调博弈点选一次即提交。Nash 需求博弈每轮从未选择开始。点击或轻触滑块轨道，也可用方向键选值。选值后才显示滑块圆点和数值。可按 Enter 或点「确认提交」提前提交。倒计时归零时自动提交最后保存的值，未选择则记为超时。双方提交后即结算，选择和收益只向配对双方展示。教师可导出完整历史。

入室期间可调整独立群体数。教师可手动截止，或启动 5–3600 秒的入室截止计时器（默认 60 秒）。可暂停、继续或重置计时。到期时若每群至少两人则自动截止，否则继续接收学生。开始前可重新开放入室，再次截止时按新名单重新随机分组。

轮次条用亮绿色标出已完成轮。当前轮带双圈，演示中为金黄色，正式实验中为紫色。待开始轮用灰色虚线表示。师生都能看到倒计时和进度条。教师可暂停和继续作答或反馈，或将当前阶段的剩余时间缩短 30 秒，最多推进至阶段边界。提前结束本轮会进入反馈（最后一轮直接结束），反馈中可直接进入下一轮；终止实验须确认。已结算收益保留，未完成配对标记为 `interrupted`，原选择保留，收益留空。研究 JSON 的 `controls` 记录教师操作、时间和轮次。学生的个人记录最新在上，仅在记录表内滚动。

教师首页的「ルーム管理」会标注 SEG 房间是「協調ゲーム」还是「ナッシュ要求ゲーム」，可通过「実験」筛选分别查看。
提交前的草稿仅本人可见，重新入室时会恢复。教师手动提前关闭作答或终止实验时，尚未提交的草稿会被丢弃。Nash 需求博弈的 JSON 和 CSV 用 `submissionSource` 区分手动提交（`manual`）和倒计时截止自动提交（`deadline`）。

## 参数与收益

正式版和演示版配置页在各整数输入框下显示「输入范围」。离开输入框或点击创建时，留空、越界和非整数的提示会显示在出错字段下。演示人数范围为 2–5,000 人。收益表会标注可用的输入格式。

| 参数         | 默认值 | 可设范围 |
| ------------ | ------ | -------- |
| 独立群体数   | 1      | 1–32     |
| 轮数         | 10     | 1–10,000 |
| 作答时间     | 30 秒  | 5–600 秒 |
| 轮间反馈时间 | 8 秒   | 3–120 秒 |

- **协调博弈。** 正式版和演示版中，修改策略名称会同步更新收益矩阵的行头和列头。在每格直接填写两个收益，左边是行方，右边是列方。行列默认均为鹿、兔，按行依次为 (4,4)、(0,3)、(3,0)、(2,2)。每轮重新抽取行方与列方，学生可见自己的位置，以便解释非对称矩阵。
  协调博弈提交后，选项按钮留在原位并锁定。双方提交后，同一张收益表高亮命中的行、列与交叉格，标明双方各自的收益。

- **Nash 需求博弈。** 两侧共用 0–1 滑块，总额为 1。建房时可选 0.1（默认）、0.01、0.005 或 0.001，整场固定，保存在研究数据 JSON 的 `settings.demandStep`。需求和不超过 1 时各得所求，超过时双方收益均为 0。按整数千分位结算，0.3 + 0.7 恰好成交。没有保存步长的旧滑块房间沿用 0.001，旧离散房间继续使用原有选项。

配置超过 32 轮时，轮次区使用紧凑进度条。在线个人和教师结果显示最近 20 个历史轮次及当前轮次。 点击「前 20 轮」逐页回看，点击「返回最新」回到当前进度。

## 配对、计时与缺席

各群独立重抽，需求博弈只跨 A/B 匹配，允许连续遇到同一人。奇数群每轮有一人轮空。在可轮空的人中（需求博弈为人数较多的一侧）优先选择历史轮空次数最少者，同次数随机抽取。轮空者无须作答，该轮收益留空。

全部配对提交或服务端截止时间到达时结束本轮。反馈期过后，由下一次已认证的房间请求开启下一轮。如果所有人关页，恢复访问时应用上一轮截止时间，到期后开启完整的新作答窗口。最后一轮直接进入结果页。一方缺答时双方当轮收益均留空，保留已提交一方的原选择，分别记录对方缺答和本人超时。实际收益为零时记录 0。

本对结算后，若全房间作答尚未结束，显示「等待其他配对完成」。全房间进入轮间反馈后，才显示「距下一轮」。 等待其他配对期间也能查看本对结果，此时倒计时显示「距作答截止」。作答结束后，全房间统一开始反馈倒计时，并一起进入下一轮。 状态切换时，倒计时保持在原位。

关页不会撤销席位，之后仍参与匹配。基础版没有永久退出或替补流程。使用原昵称和 PIN 可重入，截止后不能新增参与者。连续超过 15 秒没有服务端联系即记录疑似断线，也可能是标签页进入后台。记录区间从最后联系后 15 秒到下次联系、导出或实验结束；作答超时单独记录。

## 读取和导出数据

教师表格按群体逐轮展示。策略比例的分母为已提交选择数，含对方缺答时保留的选择，需求博弈 A/B 两侧分别计算。配对频数按行方、列方顺序（需求博弈为 A/B）。协调成功率定义为已结算配对中选择相同的比例，自定义矩阵也采用此口径。谈崩率为需求之和超过总额的配对占已结算配对的比例。分母为空时显示横线。

连续 Nash 需求的教师端将需求划分为十个区间，分别显示 A、B 分布及谈崩率。完整的精确需求和配对结果可从原始数据导出。

**研究数据 JSON** 包含完整配置、房间代码、匿名名单、固定群体及侧别、心跳缺失区间、每群每轮统计和逐人逐轮原始记录。**原始记录 CSV** 每名入组者每轮一行，含轮空记录，可用房间、群体、轮次和匿名 ID 与 JSON 联结。选择索引按配置顺序从 0 起。时间为 Unix 毫秒，`seenAt` 是服务器第一次观察到该参与者访问本轮作答窗口的时间，`submittedAt` 是收到提交的时间。人数分别统计已分组、已配对、已访问和已提交。`pay`、`total` 用字符串保存精确数值。缺失在 JSON 中为 null，在 CSV 中为空。状态含 `bye` 轮空、`timeout` 本人超时、`unmatched` 对方超时和 `settled` 已结算。导出不含昵称、PIN 或登录凭证。

新增的连续需求房间用 `demand`、`opponentDemand` 保存所见小数，两列 `choice` 字段按整数千分位记录。离散选项房间沿用从 0 开始的选项索引。

## 鹿兔研究版 v3（新建房间）

建房时选择「鹿兔研究版 v3」。原版协调博弈仍为默认，既有房间不变。正式房满150人后可结束报名，同一批参与者依次完成10人、30人和150人三种区块。教师在建房时选择正序或逆序；每块重新随机分组，学生的可见历史从头开始，研究导出保留所有区块。

每块120轮，名义上每轮为5秒作答、1秒反馈。由浏览器轮询推动阶段，实际周期要另行验证。每块先锁定10轮：10人组为8组全鹿、7组全兔；30人组中选定起点为3组、另一种2组；150人大组使用选定起点。从第11轮开始，每轮各组随机抽20%的人（2、6、30人）可以改选。未获资格或超时均沿用上轮选择。

每人每轮只用一个选择结算。系统用这个选择，分别与你所在组内的其他每个人算分。你选兔，无论对方选鹿还是兔，都得3分；你选鹿，对方选鹿得4分，对方选兔得0分。把与各人的得分取平均，就是你的本轮得分。

正式与演示的学生界面把改选状态、鹿兔按钮和单个对手收益表放在同一个选择区。按钮高亮时点一次即提交，也可点击原选项。不可选时显示锁图标，按钮颜色变淡。前 10 轮显示本组全员固定选择。上轮结果显示本组选兔比例及横条、个人选择和得分，以及从第一轮反馈起铺满内容区的最多 20 轮趋势。横轴标出轮次，纵轴标出 0%、50% 和 100%。详细规则仅在演示版显示。

教师按组查看有改选资格的人数、实际提交数、超时人数、已结算人数、策略比例及收益合计。策略比例在结算后显示。

JSON和CSV记录区块、组别、初始条件、改选资格、超时、沿用选项、上轮反馈与服务器准备提供反馈的时刻。该时间不代表参加者实际看到了画面。演示版模拟其余149席。此次不含2秒 ARUE 条件，也没有以150台设备并发或真实受试者进行验证。

## 研究解释

[主讲义第 16–21 页](../../../material/Session3-2.pdf)介绍风险占优与 Nash 讨价还价解。[KMR 补充材料第 3–7、17–18 页](../../../material/Session3-2KMR補足.pdf)使用平均收益、适应规则与罕见突变，需求博弈的示例每侧有 12 人。真人基础版每轮只观察一次私人配对，自主选择。程序不代为最佳反应，不引入人工突变。风险占优协调和对称需求例中的平分均为待检验预测，改变参数可能改变预测。正式采集前，应与教授确认反馈范围、固定侧别、人数、计时、未完成配对的处理和收敛判定方法。
