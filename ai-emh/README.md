# 独立型 EMH 実験2 AI 学生

[中文](README.zh-CN.md) · [English](README.en.md)

この独立した Node.js プログラムは、実験プラットフォームの学生 API から EMH 実験2に参加します。プラットフォームのコードを読み込まず、デモのルール型 robot も使いません。教員がルーム作成・割り当て確定・開始を行い、プログラムが指定人数の AI 学生を入室・取引させます。独立したテスト環境とデータベースを推奨します。

## 使い方

Node.js 22 以上が必要です。npm パッケージのインストールは不要です。実験プラットフォームを起動し、**EMH 実験2** のルームを作成してコードを控え、このディレクトリで実行します。

```powershell
node run.mjs
```

画面の質問に従ってプラットフォームのアドレス、ルームコード、AI 人数、モデルの種類と名前を入力します。アドレス欄に学生参加リンクまたは教員ルームのリンクを入力すると、ルームコードを自動で読み取ります。ローカルモデルは、OpenAI 互換 Chat Completions と JSON Schema による構造化出力をサポートするサービスを先に起動し、モデルを用意してください。例：Ollama の `http://127.0.0.1:11434/v1`、LM Studio の `http://localhost:1234/v1`。

ローカルモデルの Token は画面に表示せず入力します。認証が不要な場合はそのまま Enter、LM Studio などで認証が必要な場合は Token を入力します。OpenAI モードでは API キーを画面に表示せず入力します。事前に環境変数 `LOCAL_MODEL_API_KEY` または `OPENAI_API_KEY` に設定することもできます。キーは復旧ファイルや記録に保存しません。

全員が入室したら、教員画面で市場への割り当てを確定し、実験を開始します。実行中は AI の注文とエラーを表示します。Ctrl+C で停止しても学生の入室情報は削除されません。

パラメータでも指定できます。

```powershell
node run.mjs --url http://localhost:3000 --room ABCD23 --count 90 --provider local --local-url http://127.0.0.1:11434/v1 --model qwen3
node run.mjs --url http://localhost:3000 --room ABCD23 --count 90 --provider openai --model gpt-5.4-mini
node run.mjs --help
```

モデル名は利用できるものに変更してください。ローカルサービスのアドレスにホストとポートだけを指定すると、自動で `/v1` を補います。`--interval` は学生ごとの最短判断間隔（秒、既定 10）、`--timeout` はモデルの応答期限（秒、既定 20）、`--parallel` はモデルへの同時リクエスト数の上限（既定 8）です。上限に達すると次の機会まで待つため、実際の間隔は長くなる場合があります。OpenAI とローカルのどちらも JSON Schema による構造化出力を使います。`--max-output-tokens` でモデルの出力上限（既定 2048）を設定でき、対象モデルの推論 tokens を含みます。

LM Studio のモデルが長時間考えても判断を返せない場合は、起動時に `--lmstudio-fast` を指定できます。このモードは LM Studio の Responses 接続で長い思考を無効にし、判断自体はモデルが行います。対応するモデルとサービスが必要で、思考モードとは判断行動が異なる可能性があります。例えば `--lmstudio-fast --parallel 4 --max-output-tokens 1024` と指定できます。この引数を使わなければモデルサービスの既定の思考設定を維持します。

## 再入室と記録

新しい実行では `.local/runs/` に、ルームのアドレス、学生名、PIN を含む復旧ファイルと、API キーを含まない `.jsonl` 操作記録を作成します。記録には AI の判断とモデルが返す token 使用量が含まれ、AI の非公開条件が含まれる可能性があります。大切に保管してください。ファイルは Git に含まれません。中断後は同じ学生として再入室できます。 ログの `modelDurationMs` は各モデル要求の開始から応答解析までのミリ秒です。`skipReason` は `unit_changed`（取引単位の変更）、`quote_changed`（相手の注文変更）、`model_capacity`（並列枠が空くまで保留）などを示し、エラー時は `errorStage` も記録します。保留はモデルへの要求ではありません。

```powershell
node run.mjs --resume .local/runs/ルームコード-時刻-識別子.json --provider local --local-url http://127.0.0.1:11434/v1 --model qwen3
```

再入室時のプラットフォーム、ルームコードと人数は復旧ファイルから読み込みます。未登録の学生の入室は教員が受付を終了する前に完了してください。まずルームが EMH であることを確認し、最初の学生の入室後に実験2であることを確認します。誤って実験1を指定した場合、AI 学生が1人入室する可能性がありますが、取引はしません。

## 判断

AI が待機を選ぶと、プログラムは待機状態を保ちながら約 2 秒ごとに学生画面の市場情報を確認します。注文、取引、保有、Clue またはラウンドなどが変わったときに、最短判断間隔と同時実行上限を守って再びモデルに問い合わせます。秒数の経過や取引のない単位切替だけでは問い合わせません。静かな市場では参加者全員が待ち続ける場合があります。再入室後は待機状態を引き継がず、新たに判断します。ログには待機開始と終了理由、待機時間を記録します。

各 AI には自分の保有数・配当・Clue・過去の結果と公開市場情報だけを渡し、売買収支がマイナスになり得ることを説明します。モデルが買う、売る、注文、取消または待機を選び、プラットフォームが取引を検証します。完全な JSON または JSON のコードブロックを受け付け、判断を検証します。モデルのタイムアウト、エラー、不正な JSON、期限切れの判断では取引せず、**ルール型 robot に代替させません**。一時停止・休憩・カウントダウン中はモデルを呼び出しません。OpenAI を選択した場合、実験の観測情報は OpenAI に送られ、モデルと使用量に応じた費用が発生します。

`npm test` でこのプログラムのオフライン模擬テストを実行できます。現在の学生 API は専用の公開 API として安定性を保証されたものではないため、プラットフォーム更新後は互換性を再確認してください。
