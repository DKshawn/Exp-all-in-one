# Agent-Based Behavioral Experiments

[中文](README.zh-CN.md) · [English](README.en.md)

この独立した Node.js プログラムは、学生 API を通じて Double Auction、EMH、確率的進化ゲーム（SEG）の正式ルームに AI 学生を参加させます。ルームコードから実験を識別します。教員がルームの作成・受付・開始を担当します。独立したテスト環境とデータベースを推奨します。

## 使い方

Node.js 22 以上が必要です。npm パッケージのインストールは不要です。対応する正式ルームを作成し、リポジトリのルートから実行します。

```powershell
node ai-emh/run.mjs
```

画面の質問に従ってプラットフォームのアドレス、ルームコード、AI 人数、モデルの種類と名前を入力します。アドレス欄に学生参加リンクまたは教員ルームのリンクを入力すると、ルームコードを自動で読み取ります。ローカルモデルは、OpenAI 互換 Chat Completions と JSON Schema による構造化出力をサポートするサービスを先に起動し、モデルを用意してください。例：Ollama の `http://127.0.0.1:11434/v1`、LM Studio の `http://localhost:1234/v1`。

ローカルモデルの Token は画面に表示せず入力します。認証が不要な場合はそのまま Enter、LM Studio などで認証が必要な場合は Token を入力します。OpenAI モードでは API キーを画面に表示せず入力します。事前に環境変数 `LOCAL_MODEL_API_KEY` または `OPENAI_API_KEY` に設定することもできます。キーは復旧ファイルや記録に保存しません。

全員が入室したら、教員画面で市場への割り当てを確定し、実験を開始します。実行中は AI の注文とエラーを表示します。Ctrl+C で停止しても学生の入室情報は削除されません。

パラメータでも指定できます。

```powershell
node ai-emh/run.mjs --url http://localhost:3000 --room ABCD23 --count 90 --provider local --local-url http://127.0.0.1:11434/v1 --model qwen3
node ai-emh/run.mjs --url http://localhost:3000 --room ABCD23 --count 90 --provider openai --model gpt-5.4-mini
node ai-emh/run.mjs --help
```

モデル名は利用できるものに変更してください。ローカルサービスのアドレスにホストとポートだけを指定すると、自動で `/v1` を補います。`--interval` は学生ごとの最短判断間隔（秒、既定 10）、`--timeout` はモデルの応答期限（秒、既定 20）、`--parallel` はモデルへの同時リクエスト数の上限（既定 8）です。上限に達すると次の機会まで待つため、実際の間隔は長くなる場合があります。OpenAI とローカルのどちらも JSON Schema による構造化出力を使います。`--max-output-tokens` でモデルの出力上限（既定 2048）を設定でき、対象モデルの推論 tokens を含みます。

LM Studio のモデルが長時間考えても判断を返せない場合は、起動時に `--lmstudio-fast` を指定できます。このモードは LM Studio の Responses 接続で長い思考を無効にし、判断自体はモデルが行います。対応するモデルとサービスが必要で、思考モードとは判断行動が異なる可能性があります。例えば `--lmstudio-fast --parallel 4 --max-output-tokens 1024` と指定できます。この引数を使わなければモデルサービスの既定の思考設定を維持します。

Chat Completions で出力上限に達して判断が途中になったときは、該当の操作を送信せず、ログに使用した上限と `--max-output-tokens` の調整方法を表示します。

## 再入室と記録

新しい実行では `ai-emh/.local/runs/` に、ルームのアドレス、学生名、PIN を含む復旧ファイルと、API キーを含まない `.jsonl` 操作記録を作成します。記録には AI の判断とモデルが返す token 使用量が含まれ、AI の非公開条件が含まれる可能性があります。大切に保管してください。ファイルは Git に含まれません。中断後は同じ学生として再入室できます。 ログの `modelDurationMs` は各モデル要求の開始から応答解析までのミリ秒です。`skipReason` は `unit_changed`（取引単位の変更）、`quote_changed`（相手の注文変更）、`model_capacity`（並列枠が空くまで保留）などを示し、エラー時は `errorStage` も記録します。保留はモデルへの要求ではありません。

```powershell
node ai-emh/run.mjs --resume ai-emh/.local/runs/ルームコード-時刻-識別子.json --provider local --local-url http://127.0.0.1:11434/v1 --model qwen3
```

再入室時のプラットフォーム、ルームコード、実験、人数は復旧ファイルから読み込みます。旧 EMH の復旧ファイルも利用できます。新しい学生は受付締切前に入室し、開始後は登録済みの学生として再入室します。

### 回答結果

`.jsonl` にはモデルリクエストの結果を自動追記します。ルーム、学生、ラウンド、実行 ID、指定モデル名、サービスが返したモデル名、リクエストと記録の時刻、応答時間、トークン使用量、選択や取引操作、状態を記録します。応答時間は送信から応答の解析までのミリ秒です。`submitted` はプラットフォームが操作を受け付けたことを示します。約定、ペアリング、利得は教員向け結果ファイルで確認できます。

CSV はモデルリクエストごとに1行を出力します。新しい出力先を指定でき、省略時はログと同じ場所に `.results.csv` を作成します。旧形式のログでは各実行開始時のモデル情報を使い、元のログにない項目は空欄にします。

```powershell
node ai-emh/export-results.mjs ai-emh/.local/runs/ルームコード-日時-ID.json.jsonl
```

## 判断

AI が待機を選ぶと、約 2 秒ごとに学生画面を確認します。市場では注文・約定・保有などが変化し、SEG では次の回答可能なラウンドに移ると再判断します。時計の経過だけではモデルに問い合わせません。最短判断間隔と同時実行上限は引き続き適用されます。

- **Double Auction** は CDA、Call Market、Posted Offer と旧3商品CDAに対応します。モデルは自身の価値・費用と公開情報から、利用可能な操作を一つ選びます。AI の注文・購入は一操作あたり1単位です。Call の未公開注文はモデルに渡しません。
- **EMH** は実験1（固定配当）と実験2（抽選配当）に対応します。モデルは自身の配当・保有・取引履歴や公開価格を見て取引します。Clue は実験2で本人が受け取った場合に渡します。
- **SEG** は協調ゲーム、選択式・連続式のナッシュ要求ゲームに対応します。モデルは自身の位置・利得ルール・過去の個人結果から、各ラウンドで1回選びます。連続式は設定した刻みを使います。回答する前に相手の選択は渡しません。

プログラムはモデルの JSON を検証し、最新の学生画面で操作が有効なことを再確認します。タイムアウト、不正な決定、期限切れでは操作を見送り、ルール型 robot に代替させません。OpenAI を選ぶと対象の観測情報を OpenAI に送り、使用量による費用がかかります。

`npm --prefix ai-emh test` でこのプログラムのオフライン模擬テストを実行できます。現在の学生 API は専用の公開 API として安定性を保証されたものではないため、プラットフォーム更新後は互換性を再確認してください。

鹿兎・研究版 v3 では独立したローカル研究用ルームを作成し、参加者を合計 150 名にしてから入室を締め切ります。AI にも初期選択の固定、変更資格、締切を同じように適用します。モデルに渡すのは過去のグループ情報のみで、H5 では 10 人の近傍の前回選択のみです。遅れた回答を後続ラウンドに提出することはありません。接続確認では基礎版 v3 の回答時間を長めに設定し、人間の実験結果や短時間での処理能力の検証とは区別してください。
